Professional GRC Methodology
Security Audit & Risk Assessment
1
Risk Assessment
  • Inventory attack surface
  • Identify 18 findings
  • Classify by severity
  • Map to HIPAA / 42 CFR
2
Remediation Planning
  • Sequence by impact
  • Defense in depth
  • Fail-closed defaults
  • Document exclusions
3
Testing & Verification
  • Write regression tests
  • Prove tests fail first
  • Verify fixes pass
  • Measure coverage
4
Control Validation
  • Re-verify findings
  • Document live state
  • Track open items
  • Establish baseline
Key Lessons
A control can be structurally correct and semantically wrong. Reviewing the shape of a check is not reviewing the check. Claim-to-code tracing catches what code review misses.
Documentation is intent, not evidence. Comments, error messages, and architecture diagrams increase confidence in broken controls. Test against behavior, not design.
Tests are a security control. This defect was invisible to scanning and code review, visible immediately to one test. Proof requires showing the test fails against the defective code first.
Severity is impact, not effort. Assign severity by what breaks in production, not what's easy to fix. Sequence work by risk, not convenience.
